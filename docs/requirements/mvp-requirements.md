## 1. 背景与目标

craft-bean 是一家精品咖啡烘焙工坊：自己采购**生豆**（绿咖啡豆）、自行**烘焙**，将**熟豆**销售给两类客户（B2B 批发客户、B2C 零售消费者）。

当前烘焙记录、库存、进出库大多依赖表格/手工，容易出现账实不符、批次追溯困难。

**MVP 目标（M1）**：先做「内勤数字化」——把工坊内部的**供货商、生豆、烘焙、熟豆库存**管理搬上系统，建立真实、可追溯的库存账目，作为后续销售端的可信数据地基。

**总体产品路线**（分阶段）：
- **M1（本版本）**：后台内勤管理系统
- **M2**：B2C 零售微信小程序 —— 商品浏览、下单、微信支付、订单跟踪（后台发货）
- **M3**：B2B 批发客户自助 —— 客户账号、专属价格、批量下单、账单
- **远期**：多租户/多品牌扩展、报表与经营分析

> 本文件只描述 **M1**。M2/M3 需求在各自阶段另写文档。

## 2. 使用角色

| 角色 | 说明 | 权限示例 |
|---|---|---|
| 管理员（老板） | 工坊所有者 | 全部功能；账号管理、删除/作废单据、查看全部日志 |
| 员工 | 烘焙师、店员等 | 日常工作：登记烘焙、出入库；不可管理账号 |
| 只读（可选） | 如需给顾问/财务看 | 仅查看，无改动 |

> 默认一个工坊一个组织，少量用户（几人到十几人）。M1 不做复杂组织架构。

## 3. M1 功能范围

### 3.1 系统用户管理（登录与账号）
- 账号密码登录；支持「记住登录」；登出。
- 管理员可**新增 / 停用 / 启用 / 重置密码**员工账号，分配角色（管理员 / 员工 / 只读）。
- 安全：密码加密存储；连续登录失败锁定保护；重要操作需管理员。
- 用户列表：显示姓名、角色、状态、最近登录时间。

### 3.2 供货商管理
- 供货商档案：名称、联系人、电话、地址、供货品类（如埃塞/哥伦比亚生豆）、备注。
- 供货商与生豆采购关联：生豆档案登记来自哪个供货商；可按供货商查看其供过的生豆与采购记录。
- 状态管理：合作中 / 停用。

### 3.3 咖啡生豆管理
- 生豆档案：名称、产地、庄园/处理厂、豆种、处理法、烘焙度适用（可选）、默认供货商、**采购价（记录，用于成本核算）**、备注。
- **采购入库**：选择供货商 → 登记批次号/到货日期/采购量/采购单价/金额 → 自动增加生豆库存。
- 生豆库存查询：当前库存、剩余可用量、按批次追溯。
- 生豆出库记录：烘焙领用（见 3.4）、报废。

### 3.4 烘焙管理
- 烘焙批次登记：批次号（自动生成）、日期、烘焙师、使用生豆批次及用量、**烘焙曲线记录**（见下）、出炉量（产出熟豆重量）、出炉温度（可选）、一爆时间（可选）、烘焙度（浅/中/深）、烘焙机/设备（可选）、备注。
- **烘焙曲线记录（结构化适中）**：记录目标/实际关键点——烘焙度、一爆时间、出炉温度、总时长；支持关键节点文本备注（M1 不做图表，M2 后可选升级温度曲线图表）。
- 关键业务动作：登记一个烘焙批次 = **生豆出库 + 熟豆入库** 一次完成（自动联动库存）。
- 批次列表与详情：可查消耗的生豆、产出的熟豆（追溯起点）。
- 批次状态：质检中 / 可售 / 作废。

### 3.5 熟豆库存与进出库
- 熟豆商品基础信息：名称、规格（如 250g/500g/1kg）、关联豆种与烘焙批次、售价（M2 后启用）。
- **入库**：烘焙产出自动入库；手动入库（采购/调整）。
- **出库**：销售出库（**登记具体客户** + 出库类型 + 去向/备注）、样品/损耗出库、盘点调整。
- **库存预警**：熟豆商品可设置库存阈值，低于阈值时列表醒目提醒「建议补烘」，可一键查看待补烘商品。
- 库存查询：按商品看总库存；按批次看剩余量（批次追溯）。
- 库存流水：每次进出库留痕（时间、操作人、数量、类型、关联客户/单据）。

### 3.6 客户档案（基础）
- 批发客户 / 零售客户主数据：名称、类型（批发/零售）、联系人、电话、地址。
- M1 用途：销售出库时选择去向客户；M3 启用客户自助下单后再扩展专属价格、账期。

### 3.7 操作日志与审计
- 系统自动记录关键操作：登录、增删改用户、采购入库、烘焙登记、出入库、作废单据等。
- 记录内容：谁、何时、做了什么、关联单据编号。
- 管理员可查询操作日志（按人/时间/类型筛选）。

## 4. 核心业务流程

**烘焙主流程（当日工作）**
```
选择生豆批次(多个) → 填写投入量 → 烘焙完成 → 登记出炉量/烘焙度/曲线关键点
        → 系统自动：生豆-库存、熟豆+库存、生成批次追溯链
```

**出库主流程**
```
选择熟豆商品/批次 → 填数量 + 出库类型(销售/样品/损耗) + 客户(销售时) → 库存减少 → 流水留痕
```

**库存预警**
```
熟豆库存 < 阈值 → 后台醒目提示 → 决定补烘或进货 → 补烘走烘焙主流程
```

**防呆要求**
- 出库数量不能超过当前可用库存（阻止负库存）。
- 作废/回退已登记单据需管理员权限，且必须留痕，防止随意改账。

## 5. 非功能需求（M1）

- **部署**：云端部署（Web 系统），浏览器访问即可用。
- **多端**：员工用电脑（桌面浏览器）为主，移动端只需可查看（响应式即可，M1 不做原生 App）。
- **数据安全**：定期备份；敏感字段（密码）加密；系统操作留痕。
- **性能**：小型团队，常规查询即时响应即可。
- **简单优先**：界面以「少点击、快登记」为原则，烘焙师录入要快。
